# Минорное дополнение правил: найди для каждого куска его правило

На вход приходят куски данных ({{INPUT}}). Каждый из них означает то же самое,
что какое-то из правил, но записан другими словами — человек просто нашёл
более удобную формулировку. Ниже последние правила ({{RULES}}): у правила
базовый пример (raw-ввод) указан один раз, а под ним — только разночтения по
маппингу (ключ → кусок текста). Контекст последних записей: {{CONTEXT}}.

## Задача
Для каждого куска найди ключ правила, которому кусок соответствует по смыслу.

Затем пройдись по СТРОКАМ куска (строки разделяются `<br>` или переводом строки)
и сравни каждую с полем `input` всех `examples` правила. Три случая:

1. Формулировка строки уже встречается среди `examples` (тот же смысл и та же
   запись числа) — аппенд НЕ нужен, пропусти строку.
2. Строка — новое упражнение с числом (например «50 отжимания (10+40)» вместо
   «50 отжимания (+из них около 30 с колен(20+30))»): та же суть, другая запись.
   Это аппенд: ключ правила → эта строка как новый пример употребления.
3. Строка без числа и упражнения (жалобы, комментарий, состояние: «корпус и
   выше болит и клининт НО») — это НЕ данные, аппенд НЕ нужен, пропусти строку.

Для каждой строки с новым примером выдай РОВНО ОДИН аппенд — один ключ на
строку, даже если строка описывает пару упражнений. Выбирай ОСНОВНОЙ ключ
строки (первое упражнение из маппинга; для отжиманий это push_reps, для
подтягиваний pull_reps). `key` — только ключ из `mapping` правила, НИКОГДА
не id правила. Один и тот же exampleText не должен повторяться под разными
ключами.

`exampleText` обязан быть ДОСЛОВНОЙ строкой куска, целиком, включая число
в начале — «50 отжимания (10+40)», а не «отжимания (10+40)». Не пересказывай
и не обрезай формулировку: по ней позже восстановят значения ключей.

Не дублируй базовый пример правила и его `examples`: они уже есть.

Если кусок по смыслу не подходит ни к одному ключу — не выдумывай: пропусти
его (он пойдёт по другой ветке).

## Самопроверка перед ответом
- В `appends` нет строк, чья формулировка уже есть среди `examples[].input`
  правила (например «50 пресс», «50 присяд», «~5км» уже записаны — их не включать).
- В `appends` нет комментариев без числа и упражнения.
- Каждый exampleText встречается в `appends` ровно один раз.

## Формат ответа (строго один JSON)
```json
{
  "status": "success",
  "payload": {
    "appends": [
      { "key": "ключ_из_mapping", "chunk": "дословная строка ввода",
        "exampleText": "дословная строка ввода, с числом", "confidence": 0.9 }
    ],
    "confidence": 0.9
  },
  "confidence": 0.9
}
```
- `key` — ключ из маппинга правила (например push_reps), не id правила.
- `chunk` — дословная строка ввода, без пересказа.
- `exampleText` — та же дословная строка (число + упражнение), например
  «50 отжимания (10+40)» или «25 подтягивания (3 + 22)». Один аппенд на строку.
- Если аппендов нет — верни пустой массив `appends`.
