# DOCUMENTATION GOVERNANCE — уровни документации (утверждено пользователем 2026-08-30)

> Этот документ — **машинная документация** (написана агентом). Правила утверждены пользователем;
> дословная формулировка — `docs/user/README.md` + `docs/user/quotes.md` (пользовательская документация).

## Уровни приоритета

Документация — это инструкции. Любая инструкция может столкнуться с реальностью и оказаться
неправильной — поэтому ни одна из них не «истина». Инструкции просто имеют **разный вес**:
более важные перекрывают менее важные. Агенты друг другу не «не доверяют» — просто вес разный.

```
УРОВЕНЬ 1 (высший приоритет) — docs/user/
  Пользовательская документация:
  • артефакты пользователя (docs/user/artifacts/)
  • дословные цитаты пользователя + контекст (docs/user/quotes.md)

УРОВЕНЬ 2 — всё остальное: docs/, README.md, AGENTS.md
  Машинная документация (написана агентами): ROADMAP, REQUIREMENTS, DECISIONS, ...
  В спорных местах ссылается на уровень 1 («см. цитату U-…»).
```

## Правила

1. **Перекрытие.** При конфликте инструкций инструкция уровня 1 перекрывает уровень 2.
   Агент НЕ переписывает уровень 1 сам — он предъявляет конфликт пользователю и просит
   переписать/разрешить. Разрешает только пользователь.
2. **Готовность к столкновению с реальностью.** Ни одна инструкция не объявляется «истиной».
   Если реализация или действительность противоречат инструкции — это НЕ «нарушение истины»,
   а сигнал: инструкцию надо переписать (пользователем — для уровня 1, агентом с фиксацией —
   для уровня 2). До столкновения не предполагаем, что инструкция непогрешима.
3. **Формулировки вида «по уточнению заказчика», «пользователь требует»** вне `docs/user/`
   считаются ПЕРЕСКАЗОМ агента, пока не подкреплены цитатой в `quotes.md` (формат: `[U-<дата>]`).
4. **Агент может на уровне 1:** дописывать новые дословные цитаты (только по явному слову
   пользователя о том, что цитату стоит запомнить) + писать контекст к ним.
   **Не может:** изменять слова пользователя, сокращать, перевирать, удалять.
5. Переписывание машинных доков (REQUIREMENTS/DECISIONS/ROADMAP) своими формулировками без
   цитат-оснований — запрещено (это и было «вторжением», из-за которого введена эта система).

- Решения Dn, которые претендуют на «слово пользователя», обязаны иметь ссылку на цитату из
  `docs/user/quotes.md`. Решения без цитаты — инженерные решения агента (уровень 2) и не могут
  апеллировать к весу пользовательской формулировки.
- Переименовано 2026-08-30 по решению пользователя: каждый ID получил постфикс источника —
  D8…D14 = [user] (формулировка пользователя в пересказе агента, дословные цитаты отсутствуют —
  ведение цитат начато позже), D1…D7 = [agent]. Новые решения обязаны нести постфикс с первого дня.

## Правила для ROADMAP.md

- Схема архитектуры в ROADMAP (P0–P7-видение) противоречит исходному заданию
  (`docs/user/artifacts/original-task.md`, уровень 1) и актуальному релайнменту D8[user]. При ревизии:

  было двух конкурирующих версий архитектуры в машинных доках.
