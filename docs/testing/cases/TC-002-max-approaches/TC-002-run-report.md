## Найденная вариативность и исправления

Живые промежуточные ответы Gemma расходились: Router относил новую max-метрику в Branch 2; другой запуск пропускал прежние reps-значения или относил известную пару A+B в Branch 2; RuleUpdate иногда возвращал пустой `rule.keys` либо включал новую метрику в старые данные. Один повторный Structured мог также расходиться с интерпретацией RuleUpdate.

Исправления в текущем коде:

1. Router v23 явно различает неизвестную измеряемую величину, новую форму записи и уже сохранённую bare A+B-пару.
2. `conflict.js` дополняет список ключей валидными `newKeys`, если модель пропустила их в `rule.keys`.
3. Branch 3 повторно переводит весь день по замороженным правилам до обновления; значения RuleUpdate и Structured сверяются в preview. Неизвестный старый ключ или противоречивые значения останавливают preview с ошибкой вместо молчаливого выбора.
4. События сохраняют порядок дней из Cutter.

Полная последовательность фактических ответов, вход и Save-снимок — в [`TC-002-evidence.json`](TC-002-evidence.json). Ранние неудачные прогоны изолированы в scratch-копии и не меняли пользовательские данные.
