# Repair Map 10/12: сохранение минорных дополнений и временного правила

Дата: 2026-09-26. Слой: browser bundle с mock Vault; отдельно — реальные ответы локальной Gemma в изолированных core-прогонах. Источники критериев: `docs/user/artifacts/architecture.canvas`, узлы минорного дополнения и временного словаря; specs TC-001/TC-002. Пользовательские источники не изменялись.

Конкретная ошибка Save устранена. Bundle/mock проверки пунктов 10/12 проходят. Полный end-to-end статус остаётся открытым: текущий Obsidian Vault не проверялся, а повторы Gemma выявили отдельные расхождения до Save.

## Причина и изменение

В смешанном прогоне раннее предложение `rule_001` попадало в сессионный словарь как `tmp_rule_001`. Поздний RuleUpdate мог обновить этот временный ID. При Save `commitRules` сначала убирал сессионные overlays, затем применял `updateRuleId` последнего предложения ко всем предложенным правилам. В committed-журнале временного ID ещё нет, поэтому появлялось сообщение `правило tmp_rule_001 для обновления не найдено`. Правильное превью до Save этому не противоречит: оно читает сессионный словарь.

Теперь Save сначала подготавливает и проверяет изменения всех правил. Сессионный ID разрешается только при наличии исходного правила в сохранённом журнале или в списке предложений. Последовательные изменения одного временного правила объединяются в один `add`; изменение сохранённого правила остаётся `update`. Цель обновления хранится у своего предложения и не применяется к соседним правилам. В main не попадают сессионные ID и служебные `completeSnapshot`/`updateRuleId`.

Минорные аппенды из `rulesLog.tmp.json` передаются в Save как дополнения примеров, включая несколько формулировок одного ключа. Если preview events отсутствуют, используются уже проверенные значения temp-примера. Слияние повторного аппенда не мутирует прежний снимок. Temp очищается штатным UI только после успешной транзакции; при сбое записи он сохраняется для повторного Save.

Распознавание входа и промпты не менялись; изменения относятся к идентичности правил, версии и передаче проверенных примеров.
