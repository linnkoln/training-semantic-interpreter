# ROADMAP — компилятор личного диалекта → семантическая модель

> State of truth. Здесь только текущее видение, архитектура и фазы. История и решения — в `docs/DECISIONS.md`, найденные проблемы — в `docs/PROBLEMS.md`.

## Видение

Превратить захардкоженный пайплайн «отжимания/подтягивания» в **доменно-независимый компилятор** пользовательского языка:

```
грязный ввод (таблица/текст)
        │
        ▼
   Interpreter  ── 1 Vocabulary (сущности + алиасы)
        │         ─ 2 Semantic rules (when/then, версии)
        │         ─ 3 Semantic graph (part_of/successor/independent)
    ┌───┴────┐
    ▼        ▼
Structured  Unknown/Conflict
Immutable   → Rule Evolution (Dynamic | Global)
 Event           │
(snapshot)       ▼
    └────► Versioned Knowledge Base (data.json — read-only)
                  │
                  ▼
   Renderer: part_of→stacked | successor→timeline | independent→multi-line
```

**Ключевой принцип:** ввод пользователя — «программа на личном диалекте», ей нужен интерпретатор, а не LLM напрямую. LLM = наблюдатель + предлагатель изменений, но **не источник истины**. Источник истины — версионируемая база знаний.

## Четыре режима LLM

| Режим | Что делает |
|---|---|
| Parse | известно правило → конвертирует в события |
| Ambiguous | не понимает / несколько вариантов → спрашивает |
| Resolve | предлагает правило → ждёт подтверждения пользователя |
| Migrate | формирует новую версию правил (dynamic, реже global) |

## Три слоя модели

1. **Vocabulary** — сущности + алиасы (`data/vocabulary.json`)
2. **Semantic rules** — when/then правиловерсии, dynamic[] и global[] (`data/rules.json`)
3. **Semantic graph** — отношения part_of/successor/independent (`data/graph.json`)

## Релайнмент — вернуть LLM-движок (P-A…P-Q)

> Корректировка направления (2026-08-29): механика P0–P7 построена, но движок разошёлся с сутью.
> Заказчик: LLM — ПЕРВИЧНЫЙ движок распознавания/перевода «каких угодно данных» в JSON; правила — версионируемый
> **лог**, который LLM читает при переводе и пополняет при Rule Evolution. В текущей реализации LLM из рантайма
> выброшен (детерминированный регекс push/pull; `llm.chat()` не вызывается ни разу). Расхождения — D1–D9
> (DISCREPANCIES_PLAN — файл удалён 2026-09-01; `docs/PROBLEMS.md`), решение — `docs/DECISIONS.md` D8.

Целевая модель (дословно по заказчику):

```
raw input (недетерминированные данные)
   ▼
Semantic Interpreter (LLM) — распознаёт характер, выбирает путь
   ├─ 1) вписывается в последнюю структуру ─► Branch 1
   │        Structured Event (LLM): данные + последние правила из лога → JSON (готов к отрисовке)
   └─ 2) требует новых правил ─► Branch 2
            Unknown/Conflict (LLM): придумываем правило → пример-отрисовка на данных юзера
            → Rule Evolution: принял → добавить в правила отрисовки
```

| Фаза | Содержание | Критерий готовности |
|---|---|---|
| **P-E** | LLM-шлюз + промпты: `{{…}}`-подстановка + вызов `llm.chat` + валидация `{status,payload,confidence}` | AC-R2/R6; mock-вызов из рантайма |
| **P-D** | Лог правил отрисовки `rulesLog.json` (версионируемый, read для Structured Event, append для Rule Evolution) | AC-R4; версия +1 после принятия |
| **P-A** | Router (Semantic Interpreter): LLM выбирает Branch 1/2 по характеру данных | AC-R1 |
| **P-B** | Structured Event (Branch 1): данные + последние правила → событийный JSON | AC-R2 |
| **P-C** | Unknown/Conflict (Branch 2): генерация правила + пример-отрисовка | AC-R3 |
| **P-P** | Оркестратор `pipeline.next(input, state)`: Router→ветка→события/пример→Rule Evolution | AC-R1…R6 |
| **P-F** | UI: поле1=приём raw input (без сайд-эффектов); поле2=показывает закоммиченный ИЛИ предлагаемый JSON, не пишет файл до явного «Сохранить»; pipeline→preview(график+поле2)→«Принять/Сохранить»→commit→`refreshChart()` | AC-R7, AC-R9 |
| **P-Q** | QA/integration: реальный ввод юзера через всю цепочку; mock-AC10 | AC-R8 + ручной Obsidian |

Порядок: P-E‖P-D → P-A‖P-B‖P-C → P-P → P-F → P-Q (QA-гейт). Подробный план раздачи субагентами — в DISCREPANCIES_PLAN §6 (файл удалён 2026-09-01).
