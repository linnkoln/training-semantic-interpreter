## 1. Тренды и роли (цитаты quotes.md + указания пользователя 2026-08-31)

Основание: «Правила трендов: детерминированные, по форме полосок» (2026-08-31),
««тренд живёт до максимума» — смысловая логика» (2026-08-31) + указания пользователя
в чате 2026-08-31 (вечер).

1. **roles — про ОТНОШЕНИЯ; trends — про ОТРИСОВКУ.** Это разные вещи, их нельзя смешивать:
   - **roles** (отношения между компонентами: что база, что надстройка) — определяется
     СЕМАНТИЧЕСКИ, из контекста → **LLM, как и раньше**;
   - **trends** (как фигурки по графику рисовать по известным данным и правилам) —
     детерминированная отрисовка → **LLM НЕ нужен**: вычисляет детерминированный слой
     (тренд = маленькая полоска, надстройка над базой; база — полоска внизу стека,
     касается низа графика).
2. **Граница тренда — появление нового тренда.** Когда появляется новая маленькая
   полоска (второй, третий, четвёртый тренд) — старый тренд прекращается.
3. **«Тренд живёт до максимума»** — смысловая идея удобства просмотра, не жёсткое
   правило; формальная граница — только появление нового тренда.

> Решение по К2 (2026-08-31, вечер): реализация «LLM сам решает trend/stack, ответ без
> roles = НЕКОРРЕКТНЫЙ» (вариант А, fd1ab18) отклонена — она отдавала LLM отрисовку,
> которая детерминирована. Контракт после правки: LLM размечает отношения (roles),
> детерминированный слой переводит отношения в trends для отрисовки.

> всё непомеченное или одиночное рисуется обычными барами (без роли по умолчанию) 
> Трендов на такие случаи рисовать не нужно. Трендрисуется только тогда, 
> когда появляется дополнительное упражнение на группу

4. **Тренд-линии проходят через ту же логику окон и экстремумов** (пп. 2–3 раздела 2),
   что и successor-тренды (подтверждено пользователем 2026-08-31).

## 2. Подписи цифр и оформление (подтверждено пользователем 2026-08-31)

Из истории 2026-08-28 (PROBLEMS.md, все записи «ЗАКРЫТО»; DECISIONS D7):

1. **Последний (активный) тренд** — подписываются **все точки** ряда; рисуется чёрной
   жирной линией (акцент из legacy). «Последний» = узел с данными, у которого нет
   successor-потомка с данными.
2. **Ранние тренды** — подписываются **только локальные экстремумы** (пики/впадины,
   сравнение с соседями; null-пропуски игнорируются). Смысл: цифры только там, где
   значение реально информативно (прорыв/падение), иначе налезают друг на друга.
3. **Окна трендов**: старый тренд рисуется и подписывается только **до границы
   перехода** (первое появление successor-потомка с данными); после неё данные
   обнуляются — точки не засоряют верхнюю зону.
4. **Скрытые точки — `null`, а не пустая строка** — иначе мы получим пустой белый
   бокс, а это не ОК. *(правка пользователя 2026-08-31)*
5. **Легенда снизу** (`position:'bottom'`, компактные метки) — сверху она перекрывала
   цифры-подписи.
6. **`layout.padding.top: 24px`** — резерв сверху под подписи, чтобы цифры не
   обрезались краем холста.
7. **Z-порядок**: бары стека позади (`order:3, z:1`), линии трендов поверх всего
   (`order:1, z:50`).
8. **Раздельные холсты по группам** — по одному графику на part_of-группу
   («🏋️ Push», «🏋️ Pull»), раскладка семантическая из графа, не по префиксу строк.

> graph.targets» удалён): «правила такого для отрисовки быть не может. Не в юрисдикции
> отрисовщика. Такие правила определяются через rulesLog». Отрисовщик только исполняет
> правила из лога; декларативные правила (targets/цели) живут в rulesLog.
