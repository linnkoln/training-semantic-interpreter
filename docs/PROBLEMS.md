## 2026-08-28 — корневой test.js и запуск node --test на Windows
**Проблема:** (а) `node --test tests/` на node v22/Windows падает `MODULE_NOT_FOUND` — каталог трактуется как модуль. (б) автодискавери `node --test` подхватывает мёртвый корневой `test.js` (артефакт проверки, вызывает Obsidian-specific `dv.paragraph`) и валит регрессию.
**Решение:** test-скрипт в package.json указывает нативные node-glob в кавычках: `node --test "tests/**/*.test.js"` — не зависит от шелла (на Windows npm идёт через cmd без sh-glob). Корневой `test.js` закрыт на удаление в P6.

## 2026-08-28 — applyMigration не умеет добавлять НОВЫЕ правила (P4)
**Проблема:** `core/rules.js applyMigration(rules, batch)` заменяет только СУЩЕСТВУЮЩИЕ id и бросает «правило не найдено» на неизвестный. А подтверждённое предложение (Resolve) — это обычно НОВОЕ dynamic-правило, которого ещё нет в правилах.

Зафиксировано комментарием-обоснованием в коде.

## 2026-08-28 — [BLOCKER P7] dv.view не подгружает bundle; виджет «пустой» (ручной тест в Obsidian) — ЗАКРЫТО (две причины)
**Проблема:** ручной гейт P7 выявил «пустоту» — виджет не рендерится. Причин оказалось **две**:
1. **dv.view не подгружает соседние скрипты:** `dv.view("scripts/training/main")` выполняет ТОЛЬКО `main.js`; `bundle.js` (генерирует `window.TrainingCore`) никто не выполнял, а main.js лишь проверял `window.TrainingCore` — его не было.
2. **[Истинный корень] затенение глобального `dv`:** я (ошибочно) обернул main.js в `(async (dv, input) => {...})()`. Dataview выполняет view-файл как dataviewjs-блок, где `dv`/`input` — переменные В СКОПЕ, а не аргументы функции. IIFE без аргументов делал `dv === undefined` внутри → `dv.app` кидал → catch тоже не мог показать (`dv.paragraph` undefined) → полная пустота. Это же ломало и любой другой view-файл, обёрнутый так.
**Решение (P7fix):** (а) `main.js` сам читает `scripts/training/bundle.js` из vault (`app.vault.read`) и выполняет через `new Function`, выставляя `window.TrainingCore`. (б) Главное — main.js теперь ссылается на верхнеуровневый `dv` (как в рабочем v1 `45a9d5a`), НЕ затеняя его параметром. Паттерн: `(async () => { const app = dv.app; ... })()`. Верифицировано в node: read+new Function даёт полный TrainingCore; механизм dv-глобала подтверждён рабочим v1. D5 исправлено.

## 2026-08-28 — z-order отрисовки: линии за барами, новые данные за старыми — ЗАКРЫТО
**Проблема:** после миграции на семантический рендер, линии тренда (successor/independent) рисовались ЗА барами, а не поверх — потому что в новых datasets отсутствовали поля `order`/`z`, которые в leaacy (`4a0411f`) явно задавали иерархию наложения. Пользователь это заметил как «линии за графиками» и «новые данные за старыми».
**Решение (P7fix):** восстановлена z-иерархия из leaacy HEAD (`45a9d5a`/`4a0411f`):
- бары part_of (стек full/knee/assisted) → `order:3, z:1` (позади всех);
- линии successor и independent → `order:1, z:50` (поверх всего, последние по наложению).
Так в Chart.js меньше `order` рисуется последним (поверх). Ось X осталась по возрастанию дат (старые слева → новые справа), как и было. leaacy-реализация сохранена под тегом `legacy-v1` (commit `45a9d5a`) на случай полного восстановления. `npm test` → 97/97, bundle пересобран.

## 2026-08-28 — подписи цифр: белая подложка на «скрытых» точках + легенда перекрывает цифры — ЗАКРЫТО

Оба места датолаблов линий (defaultLineDatalabels и актив-tочка) исправлены. `npm test` → 97/97.

## 2026-08-28 — окна трендов: старый тренд обрезается при появлении нового (правило «не засорять верхние точки») — ЗАКРЫТО
**Проблема:** тренды `full` (старый уровень) и `max_set` (новый уровень) рисовались ОБА по всему ряду до конца — их точки дублировали/засоряли верхнюю зону (например 100 и у full, и у max_set в конце).
**Решение:** в `core/chartModel.js` каждый НЕ-последний тренд теперь рисуется только до «границы перехода» — первого индекса, где его successor-потомок (с данными) начинает существовать; после неё данные обнуляются. Последний тренд (`max_set`) рисуется до конца (как активная фаза). Это и есть правило «тренд перестаёт, когда начинается новый — чтобы не засорять верхние значения точками».
Данные (реальные): `push_full` окно 0..22 (23 точки), `push_max_set` окно 23..41 (19 точек) — без наложения. `npm test` → 97/97.

## 2026-08-28 — восстановление трендов + max_set как накладывающийся бар + подписи по экстремумам — ЗАКРЫТО
Семантическая доработка рендера по требованиям пользователя:
- **Тренды для ВСЕХ узлов successor-цепи** (и `full`, и `max_set`) — раньше рисовали только `max_set`. Определение «последнего» тренда: узел с данными, у которого нет successor-ребёнка с данными (если `push_best` пуст, последним является `push_max_set`).
- **`max_set` возвращён накладывающимся баром** поверх стека через новое декларативное поле `graph.json.targets` (без хардкода push/pull). Логика «правил отрисовки» остаётся в графе (AC11/AC4), а не в JS.
- **Подписи цифр:** последний тренд → все точки; ранние → только локальные экстремумы (пики/впадины, сравнение с соседями, null-пропуски игнорируются) через `localExtrema`; карта активности `_labelActive` остаётся сериализуемой.
**Данные:** max_set есть только в последние 19/42 дней — потому «старые тренды» начинались с середины (это реальность данных, не баг рендера). `npm test` → 97/97.

## 2026-08-29 — P-B (Structured): удвоенное экранирование паттернов в data/rulesLog.json
**Проблема:** снапшот правил в `data/rulesLog.json` (P-D, версия 1) хранит паттерны `when.pattern` с **удвоенным экранированием** (например `^отжимания.*\\\\((\\d+)...` вместо корректного `^отжимания.*\((\\d+)...`). Из-за этого `interpret()` с правилами, взятыми напрямую из лога (`getLatestRules()`), возвращал `ambiguous` и не мог подтверждать LLM-кандидатов — ломало бы AC-R6/AC-R2.
