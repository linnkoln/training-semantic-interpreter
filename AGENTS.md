# AGENTS.md — правила работы в этом репозитории (scripts/training)

> Проект: **Semantic Training Interpreter**. Управляет этим проектов **PM** (этот агент); исполнители
> (субагенты, делегированные через delegate_task) — пишут код, НО НЕ коммитят и НЕ правят docs/.

## 🔴 ПАМЯТКА (НЕПРИКОСНОВЕННО) — не сужать недетерминированный вход

> **Вход пользователя — «какие угодно недетерминированные данные» (REQ-1). Это ядро продукта, а не пограничный случай.**
> Движок распознавания и перевода — **LLM**, а не регекс/фильтр. Детерминированный код — только **верификатор** (AC10),
> никогда первичный распознаватель.
>
> **Повторяющаяся ловушка (столкнулись не раз, зафиксировать навсегда):** агент/исполнители снова и снова
> пытаются наложить детерминированный фильтр (построчный регекс под конкретные форматы `отжимания (A+B)`,
> порядок слов «число/слово первым», конкретные ключи `push_full`/`pull_max_set`, конкретный формат строки)
> поверх недетерминированных данных. **Каждый такой паттерн проектирования противоречит идее проекта и ломает его**:
> реальные данные приходят по-разному — таблицей недели, отдельными строками, произвольными фрагментами, с комментариями
> (`~6км (боли в ноге…)`, `100 отжимания одним подходом (43 в одной планке)`, `пресс`, `присяд`, `велосипед 2ч`).
> Обязательно есть дата и есть упражнения; остальное — непредсказуемо.
>
> **Правило:** LLM переводит input → готовый JSON. Детерминированный слой лишь **подтверждает/верифицирует** события
> и правила (AC10, INV-1..5), НЕ блокирует их по формату входа. Если детерминированный слой возвращает `ambiguous`/ошибку,
> потому что не покрывает форму ввода — это БАГ проекта (недокрытие домена), а не корректный ответ.
>
> Всё распознавание → LLM; детерминизм — только инварианты (иммутабельность, версии, верификация).

## Неприкосновенное (НЕЛЬЗЯ ломать)

Эти инварианты пользовательской логики защищены автопроверкой (`npm run guard`).
Любой коммит, который их нарушает, — регресс:

- **INV-1** `interpret()` чист: не мутирует `baseEvents`, не пишет на диск.
- **INV-2** данные не записываются без явного `persist()`; поле 2 не сохраняет до подтверждения.
- **INV-3** события иммутабельны; существующее событие не перезаписывается.
- **INV-4** рендер не зависит от LLM как источника истины (AC10); события при рендере не мутируются.
- **INV-5** правила/вокабулярий не редактируются кодом напрямую; версии монотонны.

Полный контракт требований пользовательской логики — **`docs/REQUIREMENTS.md`** (машинная документация;
высший приоритет — за `docs/user/`, цитаты фиксируются только по явному слову пользователя; правила — docs/GOVERNANCE.md):
REQ-1…REQ-7 (суть «любые данные → LLM → JSON → график», Rule Evolution) и UX-1…UX-3 (два поля, staging,
Save-gate). Индексы трассируются в тесты.

## Пользовательская логика (кратко, что обязательно соблюдать)

1. Поле 1 **просто принимает данные** (без побочных эффектов).
2. Поле 2 показывает **либо существующий, либо новый/предложенный JSON** и **НЕ пишет файл**, пока пользователь
   явно не разрешит сохранение.
3. Суть: «какие угодно недетерминированные данные → JSON (готовый к отрисовке); при необходимости → обновить
   правила отрисовки».

## Обязанности

- **PM (этот агент)** — единственный, кто коммитит. Перед коммитом гоняет `npm run guard` (pre-commit хук
  уже делает это). Стековые коммиты по скопам (`feat(x):`, `docs:`, `qa:`, `refactor(ui):`).
- **Исполнители (субагенты)** — пишут только свои файлы + свои тесты, НЕ коммитят, НЕ трогают `docs/`,
  `README.md`, `AGENTS.md`, `ROADMAP.md`. Проблемы репортят в формате `PROBLEM: <дата> <суть> — решение`.

## Тесты / проверки

- `npm test` — полная регрессия (`node --test "tests/**/*.test.js"`).
- `npm run guard` — то же + инварианты пользовательской логики (requirements.test.js). **Pre-commit прогоняет guard.**
- `npm run guard:full` — явный прогон guard.
- `npm run build` — пересборка `bundle.js` (обязательна после правки core/adapters/prompts).

## Как коммитить

Коммитит **только PM**, `git add <конкретные файлы>` (не `git add -A`), сообщение с областью.
Если изменение затрагивает требования/инварианты — обновить `docs/REQUIREMENTS.md` и `tests/requirements.test.js`
**в том же коммите**.
